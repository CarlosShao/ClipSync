- [ ] PC 与模拟器登录**同一个账号**
- [ ] 准备 4 组测试文件（放同一个文件夹，方便多选）：

## 1. Wave 1 — PC → 服务端落盘（工单 F1.1 ~ F1.4）

### 1.1 小文本文件 `.md` —— **F1.1（最关键，回归原缺陷）**

| 步骤 | 操作 | 预期结果 | 判定 |
|---|---|---|---|
| 1 | PC 文件管理器选中 `test.md`，Ctrl+C | — | |
| 2 | 看**桌面端** ClipSync 列表 | 出现新条目，类型 `FILE`，显示 `test.md` + 大小 | ☐ |
| 3 | **看该条目大小** | **必须非 0**（修复前是 `0 B`） | ☐ |
| 4 | 看**移动端**列表 / 通知 | 同一个条目出现 | ☐ |
| 5 | 移动端**点开该条目详情** | 显示文件名 + 大小 + `text/markdown` | ☐ |
| 6 | 看详情页**按钮** | 是【下载】【打开】【分享】，**不是**「Copy file name」 | ☐ |
| 7 | 看详情页**提示文案** | **不出现** "cannot be fetched across devices yet" | ☐ |
| 8 | 点【下载】 | 显示进度 → 完成 → 提示保存路径 | ☐ |
| 9 | 点【打开】 | 被系统应用打开（文本编辑器/浏览器） | ☐ |
| 10 | 点【分享】 | 唤起系统分享面板（可发给微信/邮件等） | ☐ |

> 第 6、7 步是**本次修复的核心**：原来的降级态（只能复制文件名）必须消失。

## 附：验收失败时的快速取证

```powershell
# 后端是否崩过（应无输出）
docker logs --tail 200 clipsync 2>&1 | findstr "EISDIR uncaughtException"

# 后端重启次数与存活时间
docker inspect clipsync --format "RestartCount={{.RestartCount}} StartedAt={{.State.StartedAt}}"

# 服务端是否真的落盘了文件
docker exec clipsync ls -la /app/uploads/files/

# 移动端实时日志（另开终端，flutter run 那个窗口直接看）
```

把失败项的现象 + 上述取证结果发我，我直接定位修复。
