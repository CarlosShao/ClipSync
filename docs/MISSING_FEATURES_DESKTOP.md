### 3.1 角色与权限管理（RBAC）— 设计要点

> 完整表结构 DDL、权限目录、种子数据、迁移兼容方案见 **`docs/rbac-design.md`**。

**角色模型（可配置，非硬编码）：**
- `super_admin`（级别 100）：产品拥有者 / 开发者。AI 大管家开顶格后门，可见数据库结构、部署架构、加密/安全细节、他人数据。
- `admin`（级别 50）：可派发给朋友做测试。有用户/设备/订阅等管理能力，但**拿不到敏感数据**——看不到库表、看不了安全实现、查不了别人数据。
- `user`（级别 10）：普通 / 企业 / VIP 用户。只能看平台公开能力，AI 绝不允许泄露内部实现、数据库、代码、他人数据。
- 自定义角色：admin 及以上可新建 `custom_*` 角色，从权限目录里自由组合权限，级别自定（不可越级赋权）。

**权限目录按 category 分组：** `admin.users` / `admin.devices` / `admin.subscriptions` / `admin.audit` / `admin.keys` / `admin.roles` + `ai.scope`（含 `ai.use_tools`、`ai.view_platform_data` 以及 6 个 🔒 敏感权限：`ai.view_database_schema`、`ai.view_deployment`、`ai.view_security_data`、`ai.view_source_code`、`ai.access_other_user_data`、`ai.explain_internal`，均只授予 super_admin）。

**安全闸门（AI 数据范围隔离）三层兜底：**
1. 后端按角色构建 system prompt，user/admin 版本明确禁止讨论库表、代码、安全、他人数据；
2. 下发给 LLM 的 tools 列表按 `ai.*` 权限过滤；
3. 敏感工具（如 `get_security_overview`、`get_protected_clips`、`explain_deployment`）执行前再校验权限。

**后台管理台需提供的 UI：**
- 角色列表 / 新建自定义角色
- 权限目录可视化（按 category 分组勾选）
- 角色-权限分配
- 用户-角色分配（含级别约束校验）
- 角色详情查看（含该角色拥有的 AI 数据范围）
