## 1. 技术选型（含理由）

| 类别 | 选型 | 版本 | 理由 |
|------|------|------|------|
| 框架 | React | 18.x | antd 5 完全兼容；19 无必要激进 |
| 语言 | TypeScript | 5.x，`strict: true` | 全量 TS，API 类型与后端共享定义 |
| 构建 | Vite | 6.x | 秒级冷启、原生 ESM、`server.proxy` 直连后端 |
| 组件库 | **Ant Design 5** | 5.2x | 与 B 方案视觉一一对应；表格/表单/抽屉/弹窗开箱即用 |
| 图表 | echarts + echarts-for-react | 5.5 / 3.x | 看板柱图/饼图/环图；按需引入减小体积 |
| 服务端状态 | TanStack Query | v5 | 列表缓存、失效刷新、加载/错误态标准化 |
| 客户端状态 | Zustand | v5 | 仅存登录态/主题/布局等 UI 态，不做服务端数据镜像 |
| 路由 | React Router | v7（library 模式） | 声明式 `<Routes>`，路由懒加载 |
| HTTP | axios | 1.x | 拦截器统一处理 Bearer/CSRF/401 刷新/错误壳 |
| 图标/日期 | @ant-design/icons、dayjs | 随 antd | antd 5 内部即 dayjs |
| Mock | MSW | 2.x | 后端 `/api/admin/*` 未就绪时前端可先行开发并联调 |
| 测试 | Vitest + Testing Library；E2E 用 @playwright/test | — | 复用根 package.json 已有的 playwright 依赖 |

**明确不做**：微前端、SSR、monorepo 工具链（turborepo/nx）、Tailwind（antd5 + CSS Modules 已够，避免双方案混用）、UI 主题运行时切换（首版亮色，深色留 antd `theme.darkAlgorithm` 扩展位）。

**包管理器**：npm（仓库根已有 `package-lock.json`，团队一致性优先）。admin-console 作为独立包放在 `src/admin-console/`，自带 `package.json` 与 lockfile，不改造根为 workspaces（避免影响 server/desktop/mobile）。

## 3. 代码规范

### 3.1 命名
- 文件/目录：组件 `PascalCase.tsx`（`UserDrawer/index.tsx`），其余 `camelCase.ts`（`queryKeys.ts`）；CSS Modules `*.module.css`
- 类型：领域类型 `PascalCase`（`AdminUser`）；API 响应壳 `ApiResp<T>`；枚举用 union type + const 对象（`OrderStatus`）
- 变量/函数：`camelCase`；布尔 `is/has/should` 前缀；事件处理 `handleXxx`；Query hook `useXxxQuery`，Mutation `useXxxMutation`

### 3.2 ESLint 9（flat config）规则集
`@eslint/js` recommended + `typescript-eslint` recommended-type-checked + `eslint-plugin-react-hooks` + `eslint-plugin-react-refresh` + `eslint-config-prettier`。额外约定：
- `no-console: warn`（utils/logger 例外）；`@typescript-eslint/no-explicit-any: error`
- `no-restricted-imports` 禁止页面间互相 import（跨页逻辑必须下沉 `components/` 或 `utils/`）
- import 顺序：`react/antd` → 三方 → `@/api` → `@/components` → `@/` → 相对路径（插件 `eslint-plugin-import` 完成）

### 3.3 Prettier / EditorConfig
继承仓库根 `.prettierrc`（semi、singleQuote、printWidth 100、endOfLine lf），admin 包内显式放一份相同配置。CI 中 `prettier --check` 与 `eslint` 平级。

### 3.4 Git 提交规范
沿用仓库现有 conventional commits 风格（如 `feat(mobile): …`）：
`feat(admin): …` / `fix(admin): …` / `chore(admin-console): …`，subject 中文可、type/scope 必须。commitlint 校验 `type(scope): subject`。分支：本 worktree `feature/admin-console` 上继续提交；推送双远端 `origin` + `cnb`；验收后合并 `dev/cnb`（遵循仓库 AGENTS.md）。

## 4. 框架规范（React / antd / Query）

1. **组件**：只写函数组件；一个文件一个主组件；>80 行 JSX 拆子组件；禁止 `forwardRef` 除非组件库级复用。
2. **服务端状态只进 TanStack Query**：组件不得直接 `axios.get` 后 `useState` 存列表。queryKey 一律走 `queryKeys.ts` 工厂，如 `queryKeys.users({ page, q, plan })`；写操作成功后按域 `invalidateQueries`。
3. **列表页标准形态**：`useTableQuery` hook 统一封装「分页 + 筛选 + 排序 + URL 同步」，返回 `{ tableProps, filters, setFilters, isFetching }`；所有表格页（用户/订单/审计/设备）同构，改需求只改一处。
4. **表单**：antd `Form` + 后端字段同名；提交走 `useMutation`；危险操作（停用/删除/退款/改角色）必须经 `ConfirmReasonModal`（原因必填，提交体带 `reason`，与后端审计字段对齐）。
5. **权限**：前端仅做 UX 裁剪——路由级 `RequireRole`，按钮级 `hasPerm('admin.users.delete')` 隐藏；**真正的鉴权以后端中间件为准**，前端不做安全假设。
6. **错误处理**：`client.ts` 拦截器统一展开后端错误壳 → `message.error`；`401` 自动用 refresh token 续期一次，失败跳登录；路由级 `ErrorBoundary` 兜底白屏。
7. **性能**：路由全部 `lazy()`；ECharts 按需注册（BarChart/PieChart/LineChart + Canvas 渲染）；表格分页不前端聚合（后端已分页）。

## 5. 样式规范

1. **antd token 单一来源**（`theme/antd.ts`）：
   ```ts
   token: {
     colorPrimary: '#5a4bd1', colorInfo: '#5a4bd1',
     borderRadius: 8, colorBgLayout: '#f4f5fa',
     fontFamily: '-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif',
     colorTextBase: '#22252e', colorLink: '#5a4bd1',
   }
   components: { Table: { headerBg: '#f7f8fc' }, Card: { headerFontSize: 14 } }
   ```
2. **CSS Modules 只做布局与草图还原**（如顶栏、KPI 卡网格），不覆盖 antd 组件内部样式；确需覆盖用 `:where()` 降特异性并注释原因。
3. **禁用行内 style 写死颜色/间距**；间距取 4 的倍数（4/8/12/16/24），字号仅 11/12/13/14/16/18/20。
4. 状态色语义统一：成功 `#16a34a`、警告 `#d97706`、危险 `#dc2626`、信息 `#2563eb`、品牌 `#5a4bd1`（与草图 B 一致，沉淀进 `tokens.css`）。
5. 数字一律 `font-variant-numeric: tabular-nums`；金额右对齐、千分位、固定 ¥（`utils/format.ts` 的 `fmtMoney`）。

## 7. 联调、Mock 与测试策略

1. **MSW 2 先行**：为 `/api/admin/*` 全量 mock（用户/订单/审计/角色…），数据形态直接取自迁移文件的真实字段（如 `payment_orders.order_no/out_trade_no/status`）。好处：前端 M1 不被后端排期阻塞；后端按同一份 `api/types.ts` 实现后切换 `VITE_ENABLE_MSW=false` 直接联调。
2. **后端对接契约**：后端同样在 `src/server/src/routes/admin/` 下实现，响应统一壳 `{ code: 0, data, message? }`，分页壳 `{ list, total, page, pageSize }`；错误壳 `{ code: number, message }`（HTTP 状态码照常）。此契约写进 `api/types.ts` 注释，作为前后端共同验收标准。
3. **测试范围（务实，不追覆盖率）**：
   - 单测：`utils/format`、`queryKeys`、`hasPerm` 权限判断
   - 组件测试：`ConfirmReasonModal`（原因必填校验）、`StatusTag`
   - E2E 冒烟（playwright，复用根依赖）：登录 → 看板渲染 → 用户列表打开抽屉 → 订单退款弹窗 → 审计筛选，5 条主链路
4. **验收门槛（每个里程碑）**：`lint / typecheck / test / build` 全绿；E2E 冒烟通过；与草图 B 并排目检布局一致；无 console error。

## 8. 部署方案（需你确认一项）

- **首选**：nginx 新增 `admin.clipchain.top` server 块，静态托管 `dist/`，`/api` 反代到 Node 服务（同源，无 CORS）。**前置条件：DNS 解析 + TLS 证书**（可用 acme.sh / certbot，或套现有 CDN）。
- **备选**：现有域名下路径 `/admin/` 挂载（零 DNS 改动，vite `base: '/admin/'`）。
- 容器化非必须（静态文件由 nginx 直接挂卷）；如需与现有 compose 体系一致，可加一个 `nginx` 卷映射即可。
