syncClipboard.ts Refactored · streaming 
async function syncClipboard(deviceId: string) {
  try {
    const items = await db.clipboard
      .where('deviceId')
      .notEqual(deviceId)
      .toArray();
    // Use a single batched message instead of N
    return ws.send(JSON.stringify({
      type: 'bulk',
      items
    }));
  } catch (e) {
    logger.error('sync failed', { deviceId, e });
    // [AI] Add retry with exponential backoff
    return null;
  }
}
AI 建议：原函数会一次性拉取所有非本设备的剪贴板条目。优化建议：① 分批发送（每 100 条一帧）避免 WS 消息体过大；② catch 块加 retry with exponential backoff；③ 用 localStorage 缓存 deviceId 避免每次查询。

Tauri 2.0 关键更新摘要

Tauri 2.0 stable 标志着从桌面优先扩展到移动端。最重要的架构变化是从全局 runtime 改为 per-window scoped runtime1，每个窗口独立管理自己的 Webview 和事件循环。这意味着资源占用更低、隔离性更强，但也要求开发者重新设计全局状态管理。

插件系统从 1.x 的单一 plugin-api 改为 manifest-based2，每个插件在 Cargo.toml 中声明 capabilities，前端通过 `@tauri-apps/plugin-*` 命名空间引入。冷启动时间从 1.x 的 ~300ms 降到 ~120ms (Linux, empty window)3。

1 Tauri 2.0 — Window Scoped Runtime v2.tauri.app
2 Plugin manifest & capabilities tauri.app/v1/guides
3 Tauri 2.0 benchmarks: cold start github.com/tauri-apps
